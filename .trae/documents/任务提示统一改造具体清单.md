# 任务提示统一改造具体清单

## 1. 目标说明

本清单基于《任务提示统一改造分析与方案》继续细化，目标不是讨论是否要改，而是明确：

- 先改哪些文件
- 每个文件具体改什么
- 改完后要验证什么
- 哪些内容本轮不建议动

本清单默认采用前一份文档中的“方案 B：推荐方案”，同时兼顾“可分阶段落地”。

## 2. 本轮改造边界

### 2.1 本轮必须解决的问题

1. 创建任务弹窗校验失败时，不再出现全局 `sonner toast`
2. 任务相关页面的成功/失败提示统一为当前页面 toast
3. 切换左侧 tab、关键筛选项或页面上下文后，旧提示自动清理
4. 顶部右上角不再同时出现“已保存”和“未保存”

### 2.2 本轮不强制解决的问题

1. 所有业务模块一次性全部接入统一 toast
2. 登录页提示体系全面重构
3. 非任务域页面的保存反馈统一
4. 全局状态系统彻底重构

## 3. 改造顺序

建议按以下顺序实施：

1. 新增统一页面 toast 能力
2. 接入任务弹窗链路
3. 接入任务相关 5 个页面
4. 调整顶部右上角状态互斥逻辑
5. 补充清理逻辑与验收

## 4. 文件级改造清单

## 4.1 新增统一页面 toast 基础能力

### 文件

- `components/PageToast.tsx`
- `hooks/usePageToast.ts`

### 具体改造项

#### `components/PageToast.tsx`

新增一个页面内提示组件，建议支持以下能力：

- 接收 `message`
- 接收 `type`
- 接收 `visible`
- 接收 `onClose`
- 支持 `success / error / info / warning`
- 固定在当前页面容器右上角或右下角
- 层级低于全局模态框，高于页面内容

建议样式目标：

- 位置属于页面容器，不挂到应用根节点
- 视觉上与当前系统风格一致
- 支持淡入淡出
- 单次只展示一条消息

#### `hooks/usePageToast.ts`

新增一个统一 hook，建议输出：

- `toastState`
- `showToast(message, type?)`
- `clearToast()`

建议内部行为：

- 新 toast 出现时覆盖旧 toast
- 自动关闭时间默认 3000ms
- 保存 timer 引用，重复调用时先清旧 timer
- 组件卸载时清理 timer

### 验收标准

- 任意任务页面接入后，不需要再自己写 `useState(notification)` + `setTimeout`
- 相同页面内提示行为统一

## 4.2 调整任务弹窗 `TaskModal.tsx`

### 文件

- `components/TaskModal.tsx`

### 具体改造项

1. 删除字段校验中的 `toast.error(...)`
2. 保留 `setError(...)` 作为前端校验失败唯一提示出口
3. 保持 `error` 区块样式不变或只做轻微增强
4. 在以下输入变化时继续清空 `error`
   - 标题
   - 负责人
   - 开始时间
   - 截止时间
5. 评估是否在 `onClose` 时显式清空 `error`

### 需要修改的逻辑点

- `handleSave()` 中：
  - 去掉所有 `toast.error`
  - 仅保留 `setError`
- `import { toast } from 'sonner'` 删除

### 联动说明

- 表单校验失败留在弹窗内
- 后端保存失败仍由父页面接管，不在弹窗内部做 toast

### 验收标准

1. 打开弹窗后故意不填标题点击保存
2. 只在弹窗内看到错误，不出现全局 toast
3. 遮罩层不再出现“模糊位置的提示”

### 验收标准

## 4.8 调整全局顶部状态 `MainLayout.tsx`

### 文件

- `layouts/MainLayout.tsx`

### 具体改造项

当前头部状态建议按优先级改成互斥显示：

1. `isSaving` 时只显示“保存中”
2. 有 `backendError` 时显示错误状态
3. `isDirty` 时显示“未保存”
4. 仅当以下条件同时成立时显示“已保存”：
   - `!isSaving`
   - `!backendError`
   - `!isDirty`
   - `showSaveSuccess`

### 建议改法

不要继续并排分别写三个 `if`，建议先计算一个统一的头部状态变量，例如：

- `headerSaveState = 'saving' | 'error' | 'dirty' | 'saved' | 'idle'`

然后只渲染一个状态块。

### 验收标准

1. 任何时刻顶部只出现一种主状态
2. 不再同时看到“已保存”和“未保存”
3. 出现后端错误时，不显示成功状态

## 4.9 保持任务保存数据流不变

### 文件

- `hooks/useTaskActions.ts`
- `hooks/useAppActions.ts`
- `store/useAppStore.ts`

### 具体改造项

本轮建议以“少改数据流”为原则：

1. 先不修改任务持久化接口和回滚逻辑
2. 先不调整 `backendError` 的存储机制
3. 先不改 `showSaveSuccess` 的触发机制
4. 仅调整前端展示规则

### 这样做的原因

- 当前主要问题在展示层
- 先收敛提示体验，风险最低
- 避免提示改造演变成状态管理重构

## 5. 建议新增的通用规范

建议在实现时同步约定以下规则：

1. 表单校验错误优先在表单内展示
2. 页面操作结果优先在页面 toast 展示
3. 全局头部只表达“持续状态”，不表达“一次性结果”
4. 页面 toast 默认只保留最新一条
5. 页面主上下文切换时必须清理 toast
6. 弹窗关闭时应清理与该次交互直接相关的提示

建议至少覆盖以下场景：

1. 创建任务时缺少标题
2. 创建任务时缺少负责人
3. 开始时间晚于截止时间
4. 保存成功后立即切换左侧 tab
5. 保存失败后立即切换左侧 tab
6. 在周计划页切换周次
7. 在执行页切换部门与季度
8. 删除任务成功与失败
9. 连续触发两次 toast，确认只保留最新一条
10. 保存成功后再次编辑，确认顶部只显示“未保存”

## 9. 推荐交付方式

如果要把这份清单直接转为开发任务，建议按下面方式拆分：

1. 任务 1：新增页面 toast 公共能力
2. 任务 2：改造 `TaskModal.tsx`
3. 任务 3：改造 `WeeklyView.tsx`、`ExecutionView.tsx`、`TaskCenterView.tsx`
4. 任务 4：改造 `WorkbenchView.tsx`、`ReviewView.tsx`
5. 任务 5：调整 `MainLayout.tsx` 顶部状态互斥逻辑
6. 任务 6：联调与回归验证

## 10. 最终建议

本轮最重要的不是“把 toast 全部换一种样式”，而是明确三件事：

1. 错误应该在离用户最近的位置反馈
2. 一次性反馈不应该跨页面残留
3. 持续状态不应该和瞬时成功提示混在一起

因此，建议你按“第一批次 -> 第二批次 -> 第三批次”推进，不要一次性扩散到所有页面。
