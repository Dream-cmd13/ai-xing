# 全量验收测试与并发权限验证清单

## 1. 文档目标

- 目标：为当前仓库 `d:\aixing\okr-ai` 提供一份可执行、可打勾、可复核的全量验收测试清单。
- 适用范围：
  - 角色权限验收
  - `RLS` 与数据库 `RPC` 验收
  - 多人同时读写与并发冲突验收
  - 前端页面权限体验与数据库最终安全边界一致性验收
- 本文基于当前已落地规则编写：
  - 角色：`Admin / Manager / Employee`
  - `Admin`：全量可见、全量可写
  - `Manager`：全公司可见，写权限以“自己负责的部门/部门树”为边界
  - `Employee`：只能修改自己的显示名称和密码；其他用户字段不可修改
  - `Employee`：默认本部门可见，任务中如为负责人/参与人/审批人，可见跨部门任务
  - 核心保存链走数据库原子 `RPC`

## 2. 验收范围

### 2.1 业务域

- `processes`

- 多用户同时操作时，是否出现脏写、越权写、静默覆盖

## 11. 并发与多人同时读写验收

### 11.1 同一用户同一记录并发修改

- 使用两个浏览器窗口登录同一账号 `E1`
- 在窗口 A 和窗口 B 打开同一份个人资料
- 窗口 A 修改姓名并保存
- 窗口 B 使用旧页面再次保存
- 预期：
  - 窗口 B 因 `row_version` 冲突失败
  - 不允许静默覆盖

### 11.2 两个管理员同时修改同一用户

- `A1` 在浏览器 A 打开某用户
- 另一个管理员账号或同管理员第二窗口在浏览器 B 打开同一用户
- A 修改角色并保存
- B 修改部门并保存
- 预期：
  - 后保存的一方出现并发冲突
  - 不允许后写静默覆盖前写

### 11.3 两个部门长同时修改同一部门树

- 使用 `M1` 的两个窗口
- 打开同一部门树节点
- 窗口 A 新增子部门并保存
- 窗口 B 删除旧子部门并保存
- 预期：
  - 其中一个保存失败，提示刷新后重试
  - 不允许出现部分成功导致树结构损坏

### 11.4 管理员与部门长同时修改同一部门

- `A1` 与 `M1` 同时打开同一部门
- `A1` 修改负责人并保存
- `M1` 修改职责并保存
- 预期：
  - 后提交一方如果版本过旧，应被拒绝
  - 不允许旧快照覆盖新负责人

### 11.5 两个普通员工同时修改同一任务

- 让两个不同账号都能访问同一任务
- A 修改任务标题并保存
- B 修改任务优先级并保存
- 预期：
  - 若 B 不是创建者，应被权限拒绝
  - 若 B 也是合法写者，则旧版本提交应被并发拒绝

### 11.6 同一流程并发发布/回滚

- 两个合法写者同时操作同一流程
- A 发布新版本
- B 基于旧页面回滚历史版本
- 预期：
  - 旧版本操作被拒绝，提示刷新
  - 不允许流程历史链断裂
