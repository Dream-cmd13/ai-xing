# 工作台“今日工作”按上海自然日判断设计

## 问题

工作台当前使用精确时间戳判断任务是否属于“今日工作”：当前时刻必须位于任务的 `startDate` 和 `dueDate` 之间。本周任务的默认日期使用 UTC 中午表示自然日，换算到上海时间为当天 20:00。因此周一 20:00 前新建的本周任务虽然属于当前周，却不会显示在“今日工作”。数据库工作台分页 RPC 和 MCP 后备分组采用相同的精确时间判断，也存在同样的问题。

## 目标行为

“今日工作”以 `Asia/Shanghai` 的自然日为准。任务开始日不晚于今天且截止日不早于今天时，任务属于今日工作。边界日期包含在内。

例如，任务的上海自然日范围为 2026-09-07 至 2026-09-13，则在 2026-09-07 当天任何时刻都应同时显示在“今日工作”和“本周工作”。在 2026-09-06 不显示为今日任务，在 2026-09-14 也不显示为今日任务。

## 修改范围

1. 提供可复用的上海自然日判断函数，将当前时刻、任务开始时间和截止时间转换为上海日历日期后比较。
2. `WorkbenchView` 使用该函数筛选今日任务。
3. MCP 仓储的后备分组使用相同语义，避免 RPC 不可用时发生行为漂移。
4. 新增前向 SQL 迁移，重定义 `mcp_get_personal_workbench_page` 的今日任务条件，使数据库分页结果按上海自然日判断。
5. 将迁移加入受控迁移清单并更新 release contract，确保旧数据库不会在代码升级后被误判为兼容。

## 数据与接口边界

- 不修改任务的 `start_date`、`due_date` 或 `target_weeks`，也不回填既有任务。
- 不改变“本周工作”和“下周工作”的周次判断。
- 同一任务可以同时出现在今日、本周和下周分组；各分组独立分页，聚合任务列表仍按任务 ID 去重。
- 开始或截止日期缺失、无效，或者截止自然日早于开始自然日时，不进入今日分组。既有任务日期一致性约束继续负责拒绝非法写入。
- 时区固定为 `Asia/Shanghai`，不依赖浏览器、Node 进程、数据库会话或 K8s 节点的本地时区。

## SQL 语义

数据库将毫秒时间戳转换为 `Asia/Shanghai` 日期，并使用数据库当前时刻对应的上海日期判断闭区间。迁移保留函数签名、权限、安全属性、分页游标和周任务逻辑，只替换今日分组条件。

迁移是新增的事务迁移。正式数据库已有迁移、回填和 readiness 结论保持有效；发布新候选版本时仅应用本次新增迁移，不重新执行任务周期回填或历史 readiness 操作。

## 测试

- 单元测试覆盖上海当天开始边界、当天截止边界、开始日前、截止日后、缺失日期和跨 UTC/上海日期边界。
- MCP 仓储测试覆盖上海当天任务同时出现在今日和本周分组。
- SQL 契约测试确认 RPC 使用上海自然日转换，不再使用当前毫秒值直接执行 `BETWEEN start_date AND due_date`。
- 运行 TypeScript 检查、生产构建安全扫描和完整 MCP 测试。

## 风险与回退

主要行为变化是任务在开始自然日的零点起即归入今日分组，而不再等待存储时间戳所表示的具体时刻。这符合界面展示自然日而非日内时刻的产品语义。

应用回退时可以回退前端和 MCP 镜像。数据库函数迁移保持向后兼容，旧应用仍可调用同一签名，不需要删除数据库对象。
