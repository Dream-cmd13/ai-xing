# 复盘周期键预检误报修正设计

## 背景与事实

`sql/2026-08-27_mcp_review_data_scan.sql` 曾只把 `YYYY-Wnn` 视为合法的复盘周期键。因此，合法的月度键 `YYYY-Mnn` 和季度键 `YYYY-Qn` 均被报告为 `REVIEW_PERIOD_KEY_INVALID`。

2026-09-02 对当前配置测试数据库进行只读查询，覆盖 18 个根/嵌套部门节点，结果如下：

- 周度键 100 条；
- 月度键 33 条；
- 季度键 12 条；
- 旧扫描的 45 条“异常”正好等于 33 条月度键加 12 条季度键；
- 真实非法键、无 `M` 的遗留月度键、复盘数组格式异常和根复盘容器格式异常均为 0。

这项修正仅调整只读诊断和发布文档，不修改任何复盘记录。

## 目标

1. 预检与当前网页、类型定义和数据库写入契约一致，认可周、月、季度三种合法键。
2. 预检继续报告真正非法的键和非数组的周期值，且不返回复盘正文。
3. 部署文档不再把历史误报的固定数量 45 当成正式库阻断项；正式库仍必须运行修正后的只读预检，真实异常数必须为 0。
4. 用自动化测试防止月度和季度键再次被误报。

## 非目标

- 不连接正式数据库，不执行迁移，不删除或改写历史复盘。
- 不把未带 `M` 的 `YYYY-MM` 当作已验证合法格式；当前测试库中该格式为 0 条，未来如出现须单独评估并规范化。
- 不改变任务日期与执行周派生逻辑。

## 设计

### 预检范围与分类

预检扫描根部门及嵌套子部门的 `reviews` 对象。它必须只依赖正式库基线已有的 `departments` 表和 JSONB 字段，不能调用候选迁移才会创建的数据库函数，因为预检发生在迁移前。周期键按以下优先级分类：

- 周度：`YYYY-W01` 至 `YYYY-W53`；
- 月度：`YYYY-M01` 至 `YYYY-M12`；
- 季度：`YYYY-Q1` 至 `YYYY-Q4`；
- 其余键：`REVIEW_PERIOD_KEY_INVALID`。

任何合法周期键的值不是 JSON 数组时，继续报告 `REVIEW_PERIOD_FORMAT_INVALID`。输出只包含节点标识、JSON 路径和原因码，不输出复盘内容。

### 文档门禁

两份部署文档改为动态门禁：现场运行修正后的只读扫描并保存安全输出；任何真实非法键、复盘容器格式错误或周期值格式错误均停止发布。删除硬编码的“45 条待修复/书面接受”表述。

### 回归验证

现有 SQL 合约测试新增断言，确认预检包含周、月、季度的合法格式与嵌套部门范围，同时仍保留真实非法键和错误周期值的诊断。随后运行相关 SQL 合约测试、迁移器测试和部署制品测试，并执行差异检查。

## 风险与回退

本改动不写数据库，风险仅限于诊断分类。若发现合法格式定义与业务契约不一致，可回退这次源代码和文档提交；现有复盘数据不受影响。
